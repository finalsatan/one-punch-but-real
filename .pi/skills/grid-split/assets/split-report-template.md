# 切分报告模板

> 这是 `grid-split` 每次切分后给使用者的报告骨架。
> `<...>` 为实际值。**使用者在终端看到的是脚本原生的彩色报告**；本模板是 Agent 转述给使用者时用的格式（含脚本无法判断的目视项）。
> 报告必须**如实**：`--dry-run` 的结论、脚本警告、目视画面结论都要照抄，不得美化。

---

## 一、切分前的 dry-run 核对（必填）

| 核对项 | 期望 | 实测 | 结论 |
|---|---|---|---|
| 源图定位 | `.md → .png` 正确 | `<分镜/EP1/EP1-场景2-九宫格.png>` | `<✓ / ✗>` |
| 尺寸自洽 | 与「比例」行一致 | `<1008x1792 colorType=2>` | `<✓ / ✗>` |
| 缝带 | 落在 `W/3`、`2W/3` 附近 | `<x=333..335 / x=670..672；y=596..598 / y=1192..1195>` | `<✓ / ✗>` |
| 9 格矩形 | 尺寸互差在容差内、无 0/负 | `<w 333..335，h 593..596>` | `<✓ / ✗>` |
| 输出 | 目录 + 文件名与预期一致 | `<…/EP1-场景2-九宫格/镜头01.png …>` | `<✓ / ✗>` |
| 会覆盖 | 无（除非显式 `--force`） | `<无>` | `<✓ / ✗>` |

## 三、自检清单

- [ ] 1. 输入解析正确（`.md → png` 或直接 `.png`）
- [ ] 2. 解码成功；源图尺寸与 3×3（或 `--rows/--cols`）假设自洽
- [ ] 3. 裁缝结果合理：缝带在预期边界附近；9 格尺寸互差在容差内
- [ ] 4. 9 张文件存在、字节 > 0、像素尺寸可读
- [ ] 5. 命名正确（`.md` → 镜号；裸 `.png` → `panel-N`），与分镜表一一对应
- [ ] 6. 未覆盖旧图（除 `--force`）
- [ ] 7. 回写只改一行（其余字节不变）
- [ ] 8. `index.json` 与产物一致
- [ ] 9. **目视**：至少 2–3 张是完整单格、无白边、内容与镜号描述相符
- [ ] 10. 警告已如实转述，未美化

> 第 9 项是脚本无法判断的，**必须真的把图读出来看**。只要 exit 0 就宣称成功，是反模式 #7。

---

## 四、后续动作（交给使用者决定）

| 项 | 说明 |
|---|---|
| 源图格子宽窄不均 | 想得到**等分**产物 → 用 `--fixed --out-dir <新目录>` 对照；想**贴合内容** → 保持默认 `auto-trim` |
| 缝没吃干净 / 吃太多 | 调 `--gutter-threshold`（降）/ `--gutter-tolerance`（升），或 `--trim-px <n>` |
| 重点格要更高清 | 不要在切图上放大。回到 `grid-storyboard` 单独为该格出图（其反模式 #5 的建议） |
| 不满意源图本身 | **不要重切第二次期望变好**。改交付文件重跑上游技能，再由 image-gen 重出九宫格 |
